Which search method finds the right aviation accident report?

What the numbers say so far

    Task A — find a known report

    120 queries written for 40 known reports. A method does well if the known report comes back near the top.

    MRR@10: how high the right report ranks (1.0 = always first, 0.5 = typically second). Recall@k: share of queries where it is in the first k results. nDCG@10: quality of the first 10. ms/query: search time. Best value in each column is highlighted; small differences may not be significant — the significance tests are in the repository.

    Task A by how the query was phrased (MRR@10)

    Each report was searched for three ways: technical keywords, a natural question, and a deliberate vocabulary mismatch that avoids the report's own words.

    Task B — find similar incidents

    300 reports used as queries. Two reports count as similar when NTSB investigators coded them alike (same defining event and a shared cause finding). Those codes are hidden from the searched text.

    P@10 (strict): share of the first 10 results that match on both event and cause. P@10: share that match on at least one. For scale, picking reports at random gives about 0.02 strict.

    Limits — read before quoting any number

    • The Task A queries were written by an AI model from the reports' own analysis text, not by an aviation engineer. A domain expert should review them.
    • Task A counts one right answer per query, so absolute scores are pessimistic. The comparison between methods is the useful part.
    • Task B's ground truth is approximate: it trusts NTSB's coding.
    • Reports longer than 512 tokens are cut for the embedding models (analysis section first).
    • One dataset, one country, 120 queries. Differences that are not statistically significant are not findings.
